# Дизайн — Чат правит план, сборка строго по кнопке

**Дата:** 2026-07-06
**Область:** App2 «Slides» (`/slides`), чат-конструктор черновиков.
**Тип:** доработка поверх `2026-07-06-chat-outline-build.md` (живой аутлайн + кнопка сборки).

## Проблема
Из наблюдения пользователя:
1. Раньше агент не создавал слайды, а писал наполнение слайдов текстом в чат → терял контекст.
2. Сейчас (после выката `0984b9b`) агент по неявному триггеру запускает сборку ВСЕЙ деки прямо посреди обсуждения. Сообщение «давай заполнять слайды, помоги наполнить их контекстом» LLM-классификатор отнёс к `build_now` (для него «заполнить слайды» = «собрать деку»), фронт получил `build=true` и запустил `doBuild()`.
3. Кнопка «Собрать через движок» непонятна пользователю — неясно, что это и зачем.

Корневая причина: **нет стадии «дорабатывать план в чате»**, а наполнение = единственный механизм (батч-сборка), который к тому же авто-триггерится из чата (JS-regex «собирай/поехали» + LLM `build_now`→`build=true`).

## Целевой UX
1. В чате агент **дорабатывает план** (аутлайн — source of truth, всегда в контексте): добавляет/удаляет/двигает/переименовывает слайды И **обогащает их `brief` на месте** по ходу обсуждения. Никогда не пишет длинный контент в чат и не теряет контекст.
2. **Заполнение слайдов + сборка движком — строго по явной кнопке в UI.** Ни одно сообщение в чате не запускает сборку.
3. Кнопки сборки переименованы и снабжены подсказками (что делают и зачем).

## Решение

### Контракт (chat_agent.py)

**`Intent.action`** += `enrich`. Полный набор: `plan | add | rewrite | delete | move | retitle | enrich | build_now | chat`.

**`AgentResult`** — убрать поле `build: bool` (мёртвый авто-путь сборки). Остаются `reply / changed / go_to`.

**`_INTENT_SYSTEM`** — добавить действие:
```
- enrich: пользователь просит наполнить/детализировать/раскрыть существующие
  слайды плана контентом — обогатить их описания (brief). НЕ создаёт слайды.
```
и уточнить формулировку `build_now` → «пользователь ЯВНО просит запустить сборку деки» (но агент сборку не делает — см. ниже).

### Новая модель `EnrichedOutline` (chat_agent.py)
```python
class EnrichedItem(BaseModel):
    index: int          # 1-based, какой слайд плана
    brief: str = ""     # обновлённое описание

class EnrichedOutline(BaseModel):
    slides: list[EnrichedItem] = Field(default_factory=list)
```

### `_enrich_briefs(client, session_id, plan, ctx, message) -> tuple[DraftPlan, AgentResult]` (новая)
- Цель — незаполненные слайды аутлайна: `s.brief and not s.filled and not s.freeform` (заполненные/freeform не трогаем, чтобы не ломать готовое).
- Если целей нет → reply «В плане пока нет слайдов для доработки — сначала набросаем структуру.», `changed=False`.
- Один LLM-вызов `client.chat_json(..., EnrichedOutline, max_tokens=1500, retries=1, extra_body={"thinking": {"type": "disabled"}})`. На вход системный промпт `_ENRICH_SYSTEM` + пользовательское: контекст чата (`ctx`), текущий аутлайн построчно (`i. {title} — {brief}` по незаполненным), запрос пользователя.
- На выход — обновлённые `brief` по `index`. Применяем **на месте прямым присваиванием** `plan.slides[idx-1].brief = new_brief` (как `filled`/`freeform` ставятся напрямую; `draft.update_slide` поля `brief` не принимает — не расширяем его ради одного места). Только для валидных 1-based индексов, попадающих в незаполненные цели.
- `draft.save_plan(session_id, plan)`, reply «Дополнил план деталями ({N} сл.).», `changed=True`.
- При исключении LLM/парсинга → fallback `AgentResult(reply=_talk(client, _PLAN_SYSTEM, ctx, message), changed=False)` (обычное обсуждение, план не тронут).

### `_ENRICH_SYSTEM` (новый промпт)
Кратко: «Ты дорабатываешь план презентации Cloud.ru. Тебе дан список слайдов (номер, заголовок, текущее описание) и запрос. Обнови ОПИСАНИЯ (brief) слайдов — добавь тезисы, факты, акценты, опираясь на обсуждение. НЕ добавляй и НЕ удаляй слайды. Верни ТОЛЬКО JSON `{"slides":[{"index":N,"brief":"..."}]}` для тех слайдов, что меняешь.»

### `run_turn` — ветки
- **`enrich`** (новая): `plan, result = _enrich_briefs(client, session_id, plan, ctx, message)`.
- **`build_now`**: больше НЕ строит и НЕ шлёт сигнал сборки. `result = AgentResult(reply="Когда план готов — нажми «Заполнить слайды» справа, чтобы собрать деку.", changed=False)`. Убрать ветку `has_targets`/`build=True` и вызов `_generate_outline` из `build_now`.
- Остальные (`plan/add/rewrite/delete/move/retitle/chat`) — без изменений. `plan` по-прежнему через `_generate_outline` (генерит структуру, если её просят).

### app.py
Без изменений. `POST /api/drafts/{id}/build` уже только по кнопке; guard «нечего собирать» остаётся.

## Фронт

### webapp/static/editor.js
- **Удалить авто-триггеры сборки в `sendAgent()`:**
  - весь regex-блок «собирай/поехали» (`if (/(^|\s)(собери…)…/i.test(message)) { … doBuild(); return; }`);
  - строку `if (res.build === true) await doBuild();` в обработчике успеха.
- `doBuild()`, `hasBuildTargets()`, `renderOutline()`, кнопка `#buildDeck` — остаются без изменений. Сборка только по клику.

### webapp/static/editor.html
- `#buildDeck`: текст «Собрать деку» → **«Заполнить слайды»**; добавить `title="Прогнать план через движок: заполнить каждый слайд контентом и собрать деку."`
- `#rebuild`: текст «Собрать через движок» → **«Улучшить через движок»**; `title` → «Пересобрать ГОТОВУЮ деку через движок с проверкой качества и автоисправлением — для полировки, не для первичной сборки.»
- Под `#buildDeck` в блоке `.outline` — строка-caption: `<div class="outline-hint">Обсуди план в чате, потом заполни слайды одной кнопкой.</div>`

### webapp/static/styles.css
- `.outline-hint` — мелкий приглушённый текст (минимальный класс, в тон существующим `.outline-*`).

## Тест-план (локально dev-сервер + прод-смоук loopback)
1. Чат-черновик, «сделай презентацию про X» → аутлайн наполнился (как раньше), сборка НЕ стартовала.
2. «наполни слайды контекстом / добавь деталей» → `brief`ʼы существующих слайдов обогатились НА МЕСТЕ, число слайдов не изменилось, сборка НЕ стартовала.
3. «собирай / поехали» текстом в чате → агент отвечает подсказкой про кнопку, сборку НЕ запускает.
4. Клик «Заполнить слайды» → слайды заполняются движком, дека реальная (существующий флоу `/build`).
5. Кнопки показывают новые названия + tooltips; caption под кнопкой на месте.
6. Прод-смоук: те же шаги через loopback, console/network без ошибок.
