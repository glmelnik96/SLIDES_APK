# Переработка UX стеклянной сборки: этап сборки, честный прогресс, лёгкие миниатюры

Дата: 2026-08-20. Согласовано с Глебом в брейншторме (визуальный компаньон, экраны в `.superpowers/brainstorm/1857-1787237041/content/`).

## Проблема

Прогон на живом проде (сессия сборки на резервной модели) показал:

1. Первые ~2,5 минуты экран выглядит мёртвым: статичный текст, прогрессбар на 0% невидим, первая «движуха» — тревожная плашка «Шаг идёт дольше обычного».
2. Этапы работы неочевидны: пользователь попадает в полный редактор, где править нечего; миниатюры-заглушки со случайными цифрами неотличимы от контента; смена сцены при заполнении — резкий прыжок.
3. «Перетащите миниатюру, чтобы поменять слайды местами» тормозит: каждая миниатюра — iframe с полной декой; каждый move — полная пересборка ленты; на каждый pointermove — querySelectorAll + elementFromPoint.
4. «Проверить и улучшить слайды» подаётся как обязательный следующий шаг, хотя стоит 1–2 мин/слайд и нужна не всегда.

## Решения (зафиксированы с владельцем)

| Вопрос | Решение |
|---|---|
| Модель этапов | **A: сборка — отдельный полноэкранный этап**, редактор после |
| Ранний выход | Кнопка «В редактор сейчас»; **сборка продолжается в фоне** с компакт-индикатором |
| Финал сборки | **B: авто-переход в редактор** без промежуточного экрана; вопросы живут маркерами «?» |
| Охват | **Стеклянный путь — дефолт веба** для загрузки документа; чёрный ящик — только API/бот |
| «Проверить и улучшить» | **Только точечная** «Улучшить этот слайд (~1–2 мин)» в панели слайда; **активна только после полного завершения сборки**; общедековая кнопка уходит из UI |
| Реализация экрана | **1а: оверлей поверх `/editor?glass=1`**, без отдельной страницы |
| Миниатюры | **2а: один слайд на iframe** + перестановка DOM без пересборки + rAF-троттлинг |

## Секция 1 — экран сборки (оверлей)

Полноэкранный слой поверх редактора с первой секунды после загрузки документа. Состав:

- **Степпер этапов** сверху: `✓ Документ → ✓ Раскладка → ⟳ Заполнение N/M → Редактор`. Рядом имя файла и кнопка «В редактор сейчас →».
- **Крупный прогрессбар** (заполненные/всего).
- **Строка телеметрии**: `⟳ Заполняю слайд 4 — «Как устроен процесс»… 23 с`; второй строкой — параллельный скаут: `подбираю макет для слайда 6`. Таймер тикает с первой секунды — это замена плашки «дольше обычного» (она удаляется). Переход на резервную модель — спокойная строка «работаю на резервной модели, шаги медленнее», не тревога.
- **Крупный центр** — последний собранный слайд (iframe одного слайда). Обновляется по мере заполнения; прыжков сцены нет.
- **Карточки вопросов** справа от центра: вопрос, топ-3 чипа макетов, поле свободного ответа, «Ответить» / «Пропустить — заполнить как есть», подпись «сборка не ждёт ответа». Контракт glass (неблокирующие вопросы, мгновенный `/glass/answer`) не меняется.
- **Лента слайдов** внизу: `✓` готов (живой мини-рендер), `⟳ + таймер` заполняется, `?` вопрос, скелет с названием раздела из плана — в очереди. **Никакого фейкового контента** в заглушках.

**Авто-переход в редактор** — когда автозаполнение исчерпано: все слайды заполнены либо остались только слайды-вопросы (они дозаполняются из редактора через карточки). Промежуточного экрана-сводки нет.

Серверный glass-контракт (`/glass/start|step|score|answer`, retryLater 45с, самовосстановление при параллельной вкладке) сохраняется как есть; переработка — клиентская.

## Секция 2 — редактор после (или во время) сборки

- **Компакт-индикатор досборки** над сценой: мини-прогресс, телеметрия («заполняю „Итоги“… 12 с»), счётчик вопросов (клик открывает карточку вопроса в правой панели). Осечки — строкой в нём же. Исчезает, когда все слайды заполнены **и** вопросов не осталось; если работа кончилась, а вопросы висят — индикатор остаётся в виде «? N вопросов ждут ответа».
- **Слайд, заполняемый сейчас, залочен** (маркер ⟳); остальные доступны для правки, перестановки, смены макета сразу.
- **«Улучшить этот слайд (~1–2 мин)»** — вторичная кнопка внизу панели слайда; послайдовый LLM-прогон (новый эндпоинт). До завершения сборки — disabled с подсказкой «доступно после сборки». Общедековая кнопка `#rebuild` удаляется из UI; серверный rebuild-эндпоинт остаётся для API/бота.

### Миниатюры и drag

- Deck-эндпоинт получает параметр «отдай только слайд N» — миниатюра грузит один слайд вместо всей деки (8 миниатюр = 8 лёгких документов вместо 8×8 рендеров).
- Drag&drop переставляет DOM-узлы миниатюр на месте; сервер подтверждает move в фоне; полная пересборка ленты — только при реальной смене контента.
- Работа на pointermove/dragover (поиск цели, подсветка, getBoundingClientRect) — не чаще раза на кадр (requestAnimationFrame).

## Секция 3 — точки входа, ошибки, тесты

**Точки входа.**
- Дропзона на главной ведёт сразу в стеклянную сборку (draft → `glass/start` → `/editor?…&glass=1`). Переключатель «Прозрачная сборка» удаляется — путь единственный для веба.
- Чёрный ящик (`/build`, очередь) — без изменений для API/бота; история и retention не трогаются.
- Ручной конструктор и чат-агент не затронуты.

**Ошибки и деградации.**
- Осечка заполнения → заглушка + маркер «!»; в конце — «N слайдов не заполнились, вставлена заглушка» в индикаторе.
- 3 осечки подряд → русская ошибка на оверлее + «Повторить»; ранний выход в редактор доступен всегда.
- retryLater 45с и самовосстановление — как есть.

**Тесты.**
- Чистая логика (стейт-машина этапов оверлея, тексты телеметрии, решения по шагам) — в errtext.js-стиле, `node --test` (расширение `tests/js/glass.test.js`).
- pytest: параметр одного слайда у deck-эндпоинта, послайдовый improve-эндпоинт, редирект дропзоны.
- e2e (MCP preview): документ → экран сборки → ответ на вопрос → ранний выход → досборка в фоне → per-slide improve; drag миниатюр без пересборки.

## Вне охвата

- Серверный glass-контракт и планировщик — не меняются.
- Диаграммный движок (фазы 0–2 большого плана) — отдельная работа.
- Drag на собранных деках, мобильная вёрстка оверлея сверх текущего адаптива.
