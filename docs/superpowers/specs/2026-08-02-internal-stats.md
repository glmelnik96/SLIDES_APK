# Свой блок статистики `/slides`: обогащение usage_events + GET /internal/stats

**Дата:** 2026-08-02 · **Статус:** согласовано с App1 (COORDINATION → «Изменения контракта»)

## Зачем

Платформа усекла usage-контракт: общая сводка отменена, у каждого инструмента свой
блок в админке. Пуш на `POST /internal/usage` снят (`9a1b51b`). Взамен App2 отдаёт
свои метрики сам — через `GET /internal/stats`.

**Срочность обогащения:** интересные разрезы (`mode`, `kind`, `section_count`,
токены, ₽, класс ошибки) живут только в `jobs`, которую ретеншен чистит через 24 ч.
Долгоживущая `usage_events` знает лишь `slides_count`. Каждый день без обогащения =
день безвозвратно потерянных разрезов. История задним числом не восстанавливается.

## Ответы App1 (зафиксированы, менять нельзя без согласования)

1. **Авторизация** — заголовок `X-Ingest-Token`, тот же секрет `USAGE_INGEST_TOKEN`
   (не отзывается, переиспользуется). Loopback-only отвергнут: на общей VM это не
   граница — App3/App4 ходят на `127.0.0.1:8012` так же свободно, а метрики несут
   email'ы. Бинд остаётся `127.0.0.1:8012`, заголовок — defense-in-depth поверх.
2. **Сигнатура** — `?since=&until=&limit=`, все опциональные. `since`/`until` —
   ISO-8601 UTC (шлюз шлёт с `Z`), полуинтервал `[since, until)`. **`limit` режет
   только ленту**, агрегаты считаются по всему периоду. Шлюз шлёт `limit=8`.
   На сбой — честный `5xx`, НЕ `200` с нулями (нули читаются как «работы не было»).
3. **Per-user разрез и лента нужны оба** (топ-5 и 8 событий достаточно).
4. **Флаг обрезки по потолку 100 слайдов — нужен** (булево в событии + счётчик в
   агрегате): «успех с оговоркой» честнее чистого `done`.

Форма ответа — из ответа App1; лишние поля не мешают, читаются известные.

## Решения этой реализации

**Обогащение `usage_events.meta`** (единственное долгоживущее хранилище):
`mode`, `kind`, `section_count`, `slides_count`, `in_tokens`, `out_tokens`,
`cost_rub`, `truncated`, `error_code`. Пустые ключи опускаем — старые строки без
них остаются валидными, агрегатор трактует отсутствие как «неизвестно».

Источник каждого поля на момент терминального хука:
- `mode`/`kind`/`in_tokens`/`out_tokens`/`cost_rub` — из строки `jobs` (её только что
  обновил `mark_terminal`); читаем Job внутри `log_render` одним запросом.
- `section_count`, `truncated` — из in-memory меты раннера (аксессоры, как `owner()`).
- `error_code` — кладёт раннер в терминальное событие (только он видит исключение).

**Класс ошибки — `build_errors.error_code(exc)`**, коды-перечисления рядом с уже
существующей классификацией `user_message`: `provider_timeout`,
`provider_connection`, `provider_ratelimit`, `provider_auth`, `provider_error`,
`plan_format`, `fill`, `assemble`, `render_unavailable`, `input_invalid`, `generic`.
Watchdog даёт `build_timeout` (ставит раннер: исключения-причины у него нет).
Наружу уходит ТОЛЬКО код, никогда текст ошибки — он может нести фрагменты документа.

**Обрезка по потолку.** Оба пути обрезки (`_cap_sections` до планирования и
`_cap_slides` после) эмитят один и тот же `_CAP_NOTICE` с префиксом `limit:`.
Раннер ловит маркер в прогресс-событиях и держит флаг в мете. Связь двух сторон
пиним тестом (`_CAP_NOTICE.startswith(runner._TRUNCATION_MARKER)`) — без импорта
движка в веб-слой (веб-тесты крутятся без установленного `htmlslides`).

**Эндпоинт `GET /internal/stats`** — БЕЗ `Depends(get_current_user)`: шлюз ходит
машинным запросом, `X-User-Id` у него нет. Пустой `USAGE_INGEST_TOKEN` → `404`
(эндпоинт выключен, нормальное состояние локалки); неверный/отсутствующий токен →
`401`. Агрегация — в Python по строкам периода (объём микроскопический: ~90 строк
за 2 месяца), а не SQL-выражениями по JSON: `meta` — JSON-колонка, и SQL-разбор
привязал бы нас к диалекту.

## Сознательно НЕ делаем

- **Не восстанавливаем историю** задним числом: `jobs` за сутки могла бы дать
  разрезы для вчерашних строк, но это разовая склейка ради ≤24 ч данных.
- **Не заводим второй секрет** — App1 явно попросил переиспользовать существующий.
- **Не кэшируем** ответ: запрос редкий (рендер админки), агрегация — миллисекунды.
- **Не отдаём `source_filename`, тексты ошибок, содержимое** — запрет из нашего же
  описания метрик, пинится тестом.
- **Не режем агрегаты по `limit`** — `limit` только для ленты (условие App1).
