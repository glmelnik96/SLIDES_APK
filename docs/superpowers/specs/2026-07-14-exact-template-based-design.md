# Точный перенос: детерминированные бренд-раскладки (без ИИ) — дизайн

**Дата:** 2026-07-14
**Статус:** черновик на согласовании
**Ветка:** skill-dev

---

## В двух словах (для не-технического ревью)

Сейчас в режиме «Точный перенос» вёрстку слайда сочиняет ИИ «с нуля». Это:
- **выглядит хуже шаблона** — ИИ импровизирует, а не раскладывает бренд-стилем;
- **медленно и с провалами** — модель не успевает, слайд падает в голую заглушку;
- **тратит токены**.

Меняем подход: **программа сама, по простым правилам, раскладывает дословный текст
слайда бренд-стилем** — карточки, колонки, крупные числа, — а что не влезает по
высоте, **ужимает масштабом** (механизм уже есть, текст не режем).

Результат: бренд-вид (карточки/числа/колонки на КАЖДОМ слайде) + дословность 1-в-1
+ **ноль токенов** на раскладку + исчезают таймауты и заглушки.

**Важная оговорка (честно):** это не байт-в-байт Figma-шаблоны из авто-режима —
те жёстко привязаны к координатам и рассчитаны на *укороченный* текст (что
противоречит дословности). Мы берём те же бренд-кирпичи (карточки, фирменные
цвета/шрифты, крупные числа) и раскладываем их «потоком», чтобы блок можно было
ужать под слайд. Визуально это гораздо ближе к шаблону, чем нынешний голый текст,
и одинаково аккуратно на всех слайдах.

---

## Цель

В exact-режиме получить слайды, визуально близкие к бренд-стилю Cloud.ru,
**детерминированно** (без вызовов ИИ), сохраняя:
- **1 исходный слайд → 1 выходной** (никогда не дробим и не склеиваем);
- **дословность текста** (ни слова не меняем, `max_chars` не применяем);
- **невыход за размер слайда** — через уже готовый авто-масштаб `.exact-fit`.

Авто-режим (планировщик + филлер) не трогаем.

## Что есть сейчас

- **Этап 1 — `build_exact_plan` / `build_exact_slide`** (`htmlslides/pipeline/exact_builder.py`):
  детерминированно строит простой фрагмент — `.content-head` + `.exact-text`
  (абзацы `.t-body-30`), списки `.exact-list`, таблицы `.exact-table`, картинки
  сбоку в `.exact-cols`. Помечает `content={"html": ..., "exact": True}`.
- **Этап 2 — `design_exact_deck` / `_design_slide`** (`htmlslides/pipeline/exact_designer.py`):
  ИИ-вёрстка freeform по протоколу меток `{{aK}}`. Медленно, таймауты (MiniMax-M3),
  уезжает от бренда. Провал проверки/сети → фолбэк на html Этапа 1.
- **Ассемблер** (`htmlslides/assembler.py:136`): exact-слайд оборачивается в
  `.exact-zone > .exact-fit`; шапка `.content-head` поднимается на уровень слайда.
- **Авто-масштаб** (`htmlslides/engine/deck.js`, `autofitExact()`): ужимает
  `.exact-fit` через `transform: scale()` до нижнего предела 0.35, измеряя
  `scrollHeight/scrollWidth`. **Текст не режется.**

## Ключевое наблюдение (почему freeform выглядел хуже и что реально можно переиспользовать)

1. **Словарь классов у freeform-ИИ урезан.** `exact_designer.py` и линтер разрешают
   только `ALLOWED_CLASSES` (`linter.py:14`): generic-примитивы
   `.row/.col/.card/.accent-block/.t-*/.content-head`. Фирменные раскладки
   (`.tcl-grid`, `.c6-grid`, `.kpi-grid`, `.g22-grid`) ИИ недоступны.
2. **Фирменные раскладки нельзя ужать.** В `deck.css` они `position:absolute` с
   фиксированными Figma-координатами (`left:61px;top:300px;width:1799px;height:660px`)
   и рассчитаны на укороченный текст. Внутри `.exact-fit` абсолютный контент не
   измеряется через `scrollHeight` и не масштабируется корректно, а фиксированная
   высота обрежет дословный текст. **Вывод: переиспользовать пиксельные шаблоны
   как есть нельзя.**
3. **Flow-примитивы — можно.** `.card` (`deck.css:87`), `.accent-block` (`:95`),
   `.row` (`:104`), `.col` (`:105`) — обычные потоковые блоки; внутри `.exact-fit`
   (ширина 1800px) они измеряются и масштабируются корректно.

Итог: строим бренд-вид из **flow-примитивов** (те же кирпичи, что были у ИИ), но
**детерминированно кодом** — консистентно, на каждом слайде, без фолбэка в голый текст.

## Новый дизайн

Заменяем ИИ-раскладку Этапа 2 **детерминированным строителем flow-раскладок** в
Этапе 1 (`exact_builder.py`). Текст дословный (экранированные атомы), `max_chars` не
применяем; фрагмент кладётся в `.exact-fit` и ужимается штатным `autofitExact()`.

### Компонент 1. Классификатор раскладки

`_choose_layout(section) -> str` — по составу секции выбирает flow-раскладку из
фиксированного набора. Логику признаков берём из `_fallback_template` (`planner.py`),
но БЕЗ ориентира на `max_chars`. Порядок проб:

- есть **таблица** → `table`;
- преобладают **картинки** (картинки есть, текста мало) → `media`;
- **1–2** числа-героя коротко (по `_NUMERIC_TOKEN`) → `hero-number`;
- список из **2–6** именованных пунктов → `cards`;
- один короткий **абзац-тезис** (1 TextBlock, коротко, без списков/чисел) → `statement`;
- иначе (проза, много абзацев, список > 6, перегруз) → `text` (безопасный дефолт).

### Компонент 2. Строители flow-раскладок

Для каждой раскладки — функция `_build_<layout>(atoms) -> (html, warnings)`,
собирающая бренд-разметку из flow-примитивов с **экранированным дословным** текстом:

- **`cards`** — `.row` c `.col`>`.card` на каждый пункт (при 4–6 — переносим в
  несколько `.row` по 3). Пункт «Имя — описание» → `.card` с именем в `.t-head-36`
  и описанием в `.t-body-30`; простой пункт → одна `.t-body-30` в `.card`.
- **`hero-number`** — на каждый числовой пункт: число крупно (`.t-number-320` для
  1 числа, иначе `.t-hero-156`) + подпись `.t-body-30`; несколько чисел — в `.row`.
- **`statement`** — один тезис крупно: `.accent-block` c `.t-hero-156` (единственный
  зелёный акцент), либо `.t-hero-156` без плашки.
- **`table`** — переиспользуем текущий рендер таблицы (`.exact-table` из `_block_html`).
- **`media`** — переиспустим текущую `.exact-cols` (картинка + текст сбоку).
- **`text`** — текущий `.exact-text`/`.exact-list` (дефолт для прозы/перегруза).

Каждый строитель начинается с `.content-head` (если есть заголовок-атом) —
ассемблер поднимет её на уровень слайда, как сейчас.

### Компонент 3. Интеграция

`build_exact_slide(section)` вызывает `_choose_layout` → соответствующий
`_build_<layout>` → возвращает `(html, warnings)`. `content={"html": ..., "exact": True}`
как сейчас — **ассемблер и `deck.js` не трогаем**. `build_exact_plan` (проход по
секциям) не меняется по сигнатуре.

### Компонент 4. Этап 2 (ИИ) — выключаем

`_build_exact` (`htmlslides/pipeline/build.py`) по умолчанию **не зовёт**
`design_exact_deck`. Файл `exact_designer.py` остаётся в репо, но из exact-пути не
вызывается (удаление — отдельным решением, не в этой задаче).

## Инварианты

- **Дословность:** весь текст экранируется и переносится из атомов дословно (как в
  текущем `_block_html`). `max_chars`/`max_items` **не применяются**. Ни ИИ, ни
  программа слова не меняют, не сокращают, не добавляют.
- **1-в-1:** число выходных слайдов = числу исходных секций; порядок сохраняется.
- **Масштаб:** любой фрагмент — flow, кладётся в `.exact-fit`; `autofitExact()`
  ужимает. Перегруженный слайд (по требованию «не дробим даже перегруженный») будет
  плотным/мелким — это **ожидаемо и допустимо**.
- **Токены:** в exact-пути **ноль** ИИ-вызовов на раскладку → нет таймаутов и заглушек.

## Тесты (TDD)

- `_choose_layout`: таблица→`table`; 3 пункта→`cards`; список из 8→`text`;
  1 число→`hero-number`; короткий абзац→`statement`; проза (2+ абзаца)→`text`;
  картинка+мало текста→`media`.
- строители: **дословность** (входной текст присутствует в выходе без изменений);
  **экранирование** (`<`, `&`, `"`); «Имя — описание» → имя в `.t-head-36`, описание
  в `.t-body-30`; `cards` из 5 пунктов даёт 5 `.card`.
- интеграция: `build_exact_slide` для секции со списком возвращает html с `.card`
  (а не только `.exact-text`); `content["exact"] is True`.
- Этап 2 off: `build_deck(mode="exact")` не обращается к ИИ-клиенту за раскладкой;
  число слайдов = числу секций.
- регресс: `tests/test_exact_builder.py`, `tests/test_build_exact.py`,
  `tests/test_exact_text.py` проходят или обновлены под новый вывод.

## Открытые решения (для этапа плана, не для дизайна)

- Точные пороги признаков классификатора (берём из `_fallback_template`:
  `_NUMERIC_TOKEN`, число пунктов списка, наличие таблицы/картинок).
- Разбивка `cards` на ряды по 3 при 4–6 пунктах (или единый `.row` с переносом).
- Порог «короткого тезиса» для `statement` (длина текста).

## Что НЕ входит в этот дизайн (YAGNI)

- Возврат ИИ в exact-путь (лёгкий ИИ-подбор — только если детерминированный выбор
  окажется слишком грубым; отдельным решением позже).
- Переиспользование пиксельных Figma-шаблонов в exact (несовместимо с дословностью).
- Изменения авто-режима, ассемблера, `deck.js`, движка масштабирования.
- Смена модели (отдельный трек: A/B через `scripts/model_eval.py`).
