Дизайнер: «уберём слайд 19, он дублирует 21 по дизайну; но 21 переделай, чтобы рамочки
стыковались контурами (без отступов, как на 19); также продублируй 19, но сделай плашки
с заливками (отступы и цвет с 20-го), а 20 удали — он дублирующий».
Маппинг на момент правки: picker-19 = `grid-2x2` (контур), picker-20 = `cards-6`
(заливка), picker-21 = `frames-grid` (динамический контур). Разрулено НЕ удалением
(id завязаны на пайплайн), а разведением по типам заливки:
- **`frames-grid` — стык контурами (без зазоров).** Было `gap:20px` на сетке и рядах.
  Стало `gap:0` + схлопывание общих линий отрицательными полями: `.fg-row + .fg-row{
  margin-top:-1px}` и `.fg-frame + .fg-frame{margin-left:-1px}`. Работает благодаря
  глобальному `box-sizing:border-box` — смежные рамки делят одну 1px-линию, как в сетке.
- **`grid-2x2` — контур → ЗАЛИВКА (был визуальным дублем frames-grid).** ⚠️ Раскладка
  (фикс CSS-grid 2×2 + `data-n`) ОТМЕНЕНА в 3-м раунде — см. подсекцию ниже; заливка как
  подход сохранена. `.g22-grid`
  переведён на CSS-grid `repeat(2,1fr)` с `gap:4px` цветом фона слайда (`background:
  var(--bg)`); `.g22-cell{background:var(--bg-card);padding:30px}` — цвет и отступ взяты
  с `cards-6` (picker-20). `data-n` даёт спец-раскладки: 1 плашка на всю зону, 3 плашки =
  2 сверху + 1 широкая снизу (без «дыры»). Обводки больше нет → 19 и 20(frames-grid) не
  дублируются: одна заливочная 2×2, вторая — контурная гибкая сетка.
- **`cards-6` (picker-20) — СКРЫТ, не удалён.** Дизайн-дубль новой заливочной `grid-2x2`.
  `id` завязан на конвейер генерации (`slide_types.py`/`planner.py`/`filler.py`/
  `chat_agent.py`), поэтому добавлен в `_HIDDEN` (`webapp/templates_api.py`) — исчез из
  ручного пикера, но файл и генерация целы. Тесты обновлены: `test_draft.py` заменил
  проверки на `cards-6` → `grid-2x2` и добавил `assert "cards-6" not in ids`.
- **Итоговый пикер:** `grid-2x2` (заливка) → picker-19, `frames-grid` (стык контурами) →
  picker-20. Проверено рендером обоих + крайних случаев.

#### `grid-2x2`: фикс-2×2 → заливочная ДИНАМИКА (правка 2026-07-21, 3-й раунд)
Дизайнер: «слайд 19 не нужен; на слайде 20 должна быть такая же структура, как на 21;
должна быть возможность добавить три ряда по 5 пунктов». В старой (до-коммит) нумерации
это = убрать фикс-сетку, а заливочный мастер сделать динамическим, как `frames-grid`, с
потолком 3 ряда × 5 плашек = 15. Итог: 2-й раунд оставил `grid-2x2` фиксированной CSS-grid
2×2 (`repeat(2,1fr)` + спец-раскладки `data-n`) — **этот кусок 2-го раунда ОТМЕНЁН**, теперь:
- **Структура — копия `frames-grid`, но с заливкой.** `.g22-grid` переведён с CSS-grid на
  `flex-direction:column;gap:4px` (зазор цветом фона слайда `var(--bg)`); ряды `.g22-row{
  display:flex;flex:1 1 0;gap:4px}` делят высоту зоны поровну, плашки `.g22-cell{flex:1 1 0}`
  делят ширину ряда поровну. Заливка `var(--bg-card)` + `padding:30px` сохранены. `data-n`
  спец-раскладок больше нет — раскладка чисто flex, как у `frames-grid` (разница только
  заливка vs контур: `gap:4px` фоном против `gap:0` + схлопывание линий).
- **Слоты — идентичны `frames-grid`:** был один список `cells` (max_items 4), стало три
  независимых слота-ряда `row1` (обяз.) / `row2` / `row3` (опц.), каждый `list max_items:5`
  с `item_slots{heading (опц., ≤24), text (обяз., ≤140)}`. Пустой ряд не рендерится
  (`{% if row %}`) = «убрать ряд». Потолок 3×5 = 15 плашек. Филлер схемо-driven
  (`filler.py._fill_template` читает `template.slots`) → смена схемы подхватывается без
  правок кода генерации; `library.validate_content` тоже схемо-driven.
- **Превью пикера** (`templates_api.py`): та же логика, что у `frames-grid` — `row1`=3
  плашки, `row2`=2, `row3`=пусто (спецкейс по имени слота, id-агностичный) → карточка
  читается как гибкая сетка.
- Проверено рендером: превью (3+2 залитых плашки), 3×5 = 15 равных залитых плашек и 1×1 =
  одна плашка на всю зону. Тесты: `1 failed, 268 passed` (единств. падение —
  предсуществующий asyncio-event-loop на Python 3.12, не связан с правкой).
- **Итоговый пикер (на момент 3-го раунда):** `grid-2x2` (заливочная динамика) → picker-19,
  `frames-grid` (контурная динамика) → picker-20; `cards-6` по-прежнему скрыт.

#### `frames-grid` УДАЛЁН — оставлена только заливочная динамика (правка 2026-07-21, 4-й раунд)
Дизайнер: «слайд 20 удали». В актуальном пикере picker-20 = `frames-grid` (контурная
динамика); после 3-го раунда он структурно дублирует `grid-2x2` (picker-19) — та же
динамика 1–3 ряда × 1–5 плашек, разница только контур vs заливка. Оставили заливочный
`grid-2x2`, контурный `frames-grid` удалён полностью:
- **Удалено:** запись из `library.json`, файл `htmlslides/templates/slides/frames-grid.html`
  (`git rm`), CSS-блок `.fg-*` из `deck.css`. Комментарии-ссылки на `frames-grid` в
  `grid-2x2.html` / `deck.css` / `templates_api.py` и intent `grid-2x2` переформулированы
  без упоминания удалённого мастера.
- **Пайплайн не затронут:** `frames-grid` был чисто ручным мастером пикера — planner
  (`by_items` 4→grid-2x2, 5-6→cards-6), filler, slide_types, chat_agent на него НЕ
  ссылались. Проверено полным grep по репозиторию.
- **Не путать с `cards-6`** (старый «слайд 20» в до-коммитной нумерации): он по-прежнему
  СКРЫТ (не удалён), id завязан на конвейер. Удалён именно `frames-grid`.
- **Итоговый пикер:** `grid-2x2` (заливочная динамика) → picker-19, дальше сразу `blank`
  → picker-20. Проверено рендером grid-2x2 + прогоном тестов.

## Как не терять контекст (процесс)
1. Любой приложенный референс (скрин/SVG) сразу копируем в `docs/slide-refs/` и
   фиксируем в этом файле — не оставляем «жить» только в чате.
2. Статус каждого пункта ведём в таблице выше; коммитим вместе с изменениями кода.
3. При старте сессии сверяем ветку (`git branch --show-current` → `template-picker`)
   и читаем этот файл вместо восстановления по памяти.
