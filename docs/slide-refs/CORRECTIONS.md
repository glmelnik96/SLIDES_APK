### 16 — statement-green — ✅ СДЕЛАНО (по тексту; скриншот утрачен)
> ⚠️ Скриншот из L1119 к этому пункту НЕ восстановлен (в сообщении было только 3
> изображения — они ушли на 14/15/quote). Реализовано строго по текстовому спеку;
> если композиция не совпадёт с исходным скрином — пере-приложи только его.
- **Растянуть фреймы на весь формат.** → рамка H1 (`.statement-box`) была узкой полосой
  посередине (`top:300;height:300`, сверху пустой band). Растянул: `top:200;height:400`
  (200→600) — рамка занимает верхние ~55%, плашка+стрелки+точки — низ, слайд не «куцый».
- **Квадратные стрелки (как на слайдах 3/5).** → это тот же глиф-уголок `_arrow.html`
  (`.brand-arrow`), что в `section-frame` (3/5) и `contacts`. Заменил inline-копию в
  `statement.html` на общий партиал (`{% for _ in range(4) %}{% include "_arrow.html" %}`),
  размер акцента 180px через `.statement-tiles .brand-arrow`.
- **Правило: мало текста → стрелки остаются; много → убираются.** → в `statement.html`
  считаем `text_heavy = (len(title)+len(highlight)) > 75` (пороги по лимитам слотов:
  title≤40, highlight≤90). При перегрузе на секцию вешается `.statement--wide` →
  CSS прячет `.statement-tiles` и растягивает `.statement-plate` на весь формат (1800px).
  Правит ОБА мастера (statement тёмный + statement-green) — общий шаблон.

### 18-19 — динамические рамки (`frames-grid`) — ✅ СДЕЛАНО
Новый мастер `frames-grid` (контентный, тип `content`). Скрина к пункту не было —
это чисто поведенческий спек, реализован по тексту.
- **1..5 рамок в ряду, ужимаются/растягиваются по ШИРИНЕ ряда.** → `.fg-frame{flex:1 1 0;
  min-width:0}` — рамки делят ширину ряда поровну: добавил соседа → все ужались, убрал →
  оставшиеся растянулись. Верхний предел 5 — через `max_items:5` слота-ряда.
- **1..3 ряда, добавление/удаление; ряды делят ВЫСОТУ зоны поровну.** → три независимых
  слота `row1` (обяз.) / `row2` / `row3` (опц.), `.fg-row{flex:1 1 0}`. Пустой ряд не
  рендерится (`{% if row %}`) — это и есть «убрать ряд». Тот же паттерn, что stats-row
  (stats/stats2): вложенные списки в UI-билдере не поддерживаются (`editor.js`
  `renderItem` не рекурсивен), поэтому ряды — плоские слоты-списки, а не список списков.
- **Текст рамки — от верхне-левого края** (правило проекта): `.fg-frame{justify-content:
  flex-start;align-items:flex-start}`, одинаковый padding 30px. Заголовок рамки зелёный
  (`.fg-name`, опц.), тело — `--fg-body` (`.fg-text`).
- Превью пикера (`webapp/templates_api.py`): row1 = 3 рамки, row2 = 2, row3 = пусто —
  карточка мастера читается как гибкая сетка, а не один длинный ряд.
- Проверено рендером крайних случаев: 3×5 = 15 равных рамок и 1×1 = одна рамка на всю
  зону — оба раскладываются корректно.

## Как не терять контекст (процесс)
1. Любой приложенный референс (скрин/SVG) сразу копируем в `docs/slide-refs/` и
   фиксируем в этом файле — не оставляем «жить» только в чате.
2. Статус каждого пункта ведём в таблице выше; коммитим вместе с изменениями кода.
3. При старте сессии сверяем ветку (`git branch --show-current` → `template-picker`)
   и читаем этот файл вместо восстановления по памяти.
