# Slides App — генерация презентаций Cloud.ru в браузере

Веб-приложение (**App2**) для генерации презентаций на моделях Cloud.ru
Foundation Models. Работает **за шлюзом**, который аутентифицирует пользователей
и проксирует запросы; приложение многопользовательское — у каждого своя история
и доступ только к своим сборкам. Движок (LLM-роли, генератор HTML-дек
`htmlslides`, бренд-шаблон Cloud.ru и шрифты SB Sans) **вшит в репозиторий** —
внешние проекты для работы не нужны.

---

## Возможности

- **HTML-презентация** — документ (`md` / `txt` / `docx` / `pptx`) превращается в
  одну самодостаточную HTML-деку в бренде Cloud.ru, которую можно редактировать
  прямо в браузере. (PPTX-режимы из webapp убраны — App2 строит только HTML.)
- **«Точный перенос (1 в 1)»** — опция-чекбокс на экране загрузки. Вёрстка каждого
  слайда строится **детерминированно кодом, без ИИ на раскладку**: 1 исходный
  слайд → 1 выходной, весь текст переносится **дословно** (ничего не режется и не
  перефразируется), меняется только оформление под бренд Cloud.ru. Классификатор
  подбирает бренд-раскладку (карточки / крупные числа / тезис / колонки), числовая
  таблица становится настоящим bar-chart, перегруз ужимается авто-масштабом
  `.exact-fit`. Плюсы против ИИ-режима: быстрее, без таймаутов/заглушек, ноль токенов.
- **Редактор HTML-деки в браузере:**
  - правка текста по месту (клик по тексту → редактирование);
  - **чат-правки слайда** — инструкция на естественном языке («сделай заголовок
    короче», «добавь пункт про безопасность»), и модель переписывает текущий слайд;
  - экспорт всех слайдов в **PNG (ZIP)** или скачивание самой **HTML-деки**.
- **Многопользовательский режим за шлюзом:** личность берётся из доверенных
  заголовков `X-User-Id` / `X-User-Email`, история и сборки изолированы по
  пользователю (чужая сессия → `404`, без утечки факта существования).
- **Очередь сборок:** до `BUILD_WORKERS` сборок идут параллельно (по умолчанию 3),
  остальные ждут в пуле; общий потолок задач (`QUEUE_MAX_ACTIVE`) и лимит на
  пользователя (`USER_QUEUE_LIMIT`) — предохранители от перегруза, с прогрессом по каждой.
- **История** последних сборок (в БД) с возможностью открыть результат заново.

## Как это работает

```
Браузер ──► Шлюз (auth, +X-User-*, снимает префикс /slides)
               │  POST /api/jobs (файл)
               ▼
         FastAPI (webapp/) ──► пул воркеров ──► движок htmlslides (MiniMax-M3)
               ▲
               │  SSE GET /api/jobs/{id}/events
               └── прогресс стадий в реальном времени
```

- Приложение — **один процесс FastAPI** + SQLite. Никаких Redis, Celery, Docker, S3.
- Шлюз — единственная публичная точка входа: он аутентифицирует пользователя,
  подставляет `X-User-*` (стирая клиентские копии) и проксирует на `127.0.0.1:8012`,
  **снимая префикс** `/slides`. Роуты живут в корне, а фронт добавляет префикс
  (`APP_PREFIX`) ко всем URL в браузере.
- Прогресс пробрасывается через **Server-Sent Events** (шлюз проксирует HTTP-стрим,
  не WebSocket): стадии разбор → планирование → заполнение → сборка → проверка → готово.
- Сборки выполняются **параллельно** пулом из `BUILD_WORKERS` воркеров (по умолчанию
  3); остальные ждут в очереди. Конкурентность к Cloud.ru FM отдельно ограничена
  (`CLOUDRU_MAX_INFLIGHT` в клиенте пайплайна), поэтому число воркеров можно
  поднимать безопасно, не упираясь в лимит запросов аккаунта.
- **Перезапуск безопасен:** при старте orphaned-задачи (queued/running, чья
  in-memory очередь потеряна) помечаются `failed`; фоновая ретенция удаляет
  сессии и строки Job старше `RETENTION_HOURS`.
- **HTML-режим** строится на MiniMax-M3 через Cloud.ru FM (модель по умолчанию,
  переопределяется env `CLOUDRU_MODEL` для A/B); vision-роли (разбор брифа,
  визуальная проверка) используют мультимодальную Kimi-K2.6. Чат-правки
  переиспользуют тот же движок — модель переписывает один `<section>` слайда с
  соблюдением бренд-правил Cloud.ru. В режиме «Точный перенос» ИИ на раскладку
  **не вызывается** — вёрстка детерминированная.
- Готовый `deck.html` и PNG лежат в рабочей папке сессии (по умолчанию во временной
  директории ОС; путь можно переопределить через переменную окружения
  `SLIDESBOT_WORKDIR`).

## Структура репозитория

```
webapp/        FastAPI-приложение: маршруты, очередь, SSE-прогресс, редактор, чат, статика
  config.py      конфигурация App2 (APP_PREFIX, PORT, DB_URL, лимиты, ретенция)
  auth.py        личность из X-User-* (доверенные заголовки шлюза), upsert юзера
  db/            SQLAlchemy-модели (User, Job) + async-движок/сессии
  jobs_repo.py   доступ к Job: создание, история по юзеру, терминальный статус
  retention.py   reconcile orphaned-задач при старте + фоновая чистка по TTL
  runner.py      очередь сборок (глобальный лимит + лимит на пользователя)
llm/           клиент Cloud.ru FM, роли и промпты
htmlslides/    генератор HTML-деки (MiniMax-M3) + шаблоны, шрифты, бренд-правила
  pipeline/      разбор → планирование → заполнение → сборка → vision-QA;
                 exact_builder.py — детерминированная вёрстка режима «Точный перенос»
renderers/     рендереры слайдов
scripts/       вспомогательные утилиты движка (рендер PNG для vision-QA)
schemas/       Pydantic-модели
skill_assets/  бренд-шаблон Cloud.ru (.pptx) и справочные материалы
deploy/        systemd-юнит (app2.service) для запуска как апстрим шлюза
tests/         автотесты приложения (без обращений к сети)
```

## Установка

Требуется **Python 3.10+**.

```bash
# 1. Клонировать репозиторий
git clone https://github.com/glmelnik96/SLIDES_APK.git
cd SLIDES_APK

# 2. Виртуальное окружение
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

# 3. Зависимости приложения и движка (всё вшито в репозиторий)
pip install -e ".[dev]"

# 4. Браузер для рендера PNG (headless Chromium)
playwright install chromium

# 5. Ключ Cloud.ru
cp .env.example .env        # Windows: copy .env.example .env
#   затем впишите в .env свой CLOUDRU_API_KEY
```

`.env` (единственное обязательное поле):

```dotenv
CLOUDRU_API_KEY=ваш-ключ-cloud.ru
# необязательно — переопределить базовый URL Cloud.ru FM:
# CLOUDRU_BASE_URL=https://foundation-models.api.cloud.ru/v1
```

## Запуск (локально, без шлюза)

```bash
python -m webapp
# или: ./start.sh  (macOS/Linux)   |   start.bat  (Windows)
```

Порт берётся из `PORT` (по умолчанию `8000` локально, `8012` за шлюзом).
Для локальной работы без шлюза задайте `DEV_USER_ID` в `.env` — иначе каждый
запрос к API вернёт `401` (личность ожидается из заголовка `X-User-Id`).

Откройте в браузере **http://127.0.0.1:8000**: загрузите файл → «Создать
презентацию» → наблюдайте прогресс; по готовности автоматически откроется
редактор HTML-деки с чатом и экспортом.

### Интерактивный прогон перед редеплоем

Чтобы покликать приложение в браузере ровно как за шлюзом (но без него) —
например, проверить реальную сборку/чат-правки/экспорт перед выкаткой на VM:

```bash
python scripts/devserver.py            # http://127.0.0.1:8000
python scripts/devserver.py --port 8010 --user qa   # другой порт/юзер
```

Лаунчер эмулирует шлюз локально: подставляет `DEV_USER_ID` (нет `401` без
заголовков), убирает префикс (`APP_PREFIX=""`, браузер живёт в корне), а
`CLOUDRU_API_KEY` берёт из `.env`. Прод этим скриптом не пользуется —
`app2.service` запускает `python -m webapp` с боевыми переменными.

## Деплой за шлюзом (App2)

Шлюз — единственная публичная точка входа. Он аутентифицирует пользователя,
подставляет доверенные `X-User-Id` / `X-User-Email` (стирая любые клиентские
копии) и проксирует HTTP (со стримингом для SSE) на апстрим `127.0.0.1:8012`,
**снимая префикс** `/slides`.

```bash
# на VM
sudo useradd -r -m -d /opt/app2 app2
sudo -u app2 git clone <repo> /opt/app2 && cd /opt/app2
sudo -u app2 python -m venv .venv
sudo -u app2 .venv/bin/pip install .
# Chromium для PNG-рендера И vision-QA. ВАЖНО: ставить в дерево приложения, а не в
# ~/.cache — иначе ProtectHome=true в app2.service скроет браузер от сервиса и
# vision-QA молча отключится (см. Environment=PLAYWRIGHT_BROWSERS_PATH в юните).
sudo -u app2 PLAYWRIGHT_BROWSERS_PATH=/opt/app2/.playwright .venv/bin/playwright install chromium
sudo -u app2 cp .env.example .env                    # заполнить значения

sudo cp deploy/app2.service /etc/systemd/system/app2.service
sudo systemctl daemon-reload && sudo systemctl enable --now app2
journalctl -u app2 -f
```

Ключевые переменные в `.env` (полный список — в `.env.example`):

| Переменная         | Назначение                                                        |
|--------------------|-------------------------------------------------------------------|
| `CLOUDRU_API_KEY`  | ключ Cloud.ru FM (обязателен)                                     |
| `APP_PREFIX`       | префикс шлюза, в проде `/slides`                                  |
| `PORT`             | порт апстрима, по контракту `8012`                                |
| `DB_URL`/`DATA_DIR`| SQLite-история и каталог результатов                              |
| `BUILD_WORKERS`    | сколько сборок идут параллельно (по умолчанию 3)                  |
| `QUEUE_MAX_ACTIVE` | общий потолок задач в системе (running + waiting), предохранитель |
| `USER_QUEUE_LIMIT` | сколько задач один пользователь может держать в очереди           |
| `CLOUDRU_MODEL`    | переопределить модель по умолчанию (`MiniMaxAI/MiniMax-M3`) для A/B|
| `RETENTION_HOURS`  | TTL результатов (сессии + строки Job старше — удаляются)          |
| `DEV_USER_ID`      | **в проде пусто** (иначе отсутствие `X-User-Id` не даст 401)      |

**Egress.** Приложению нужен исходящий доступ только к Cloud.ru FM
(`foundation-models.api.cloud.ru`, HTTPS/443). Бренд-материалы (шаблон, шрифты
SB Sans) и Chromium для рендера PNG — локальные, внешний доступ к ним не требуется.

**Перезапуск безопасен:** при старте orphaned-задачи помечаются `failed`, поэтому
зависших «в процессе» строк после рестарта не остаётся.

## Замечания

- Аутентификация — **на стороне шлюза**; приложение доверяет только заголовкам
  `X-User-*` и само логин не выполняет. Не публикуйте апстрим `:8012` напрямую.
- Бренд-материалы Cloud.ru (шаблон, шрифты SB Sans) включены в репозиторий и
  используются движком офлайн.
